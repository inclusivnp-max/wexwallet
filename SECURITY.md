# Безопасность

Это кошелёк: ошибка здесь стоит пользователю денег, а не удобства.
Документ описывает, от чего проект защищает, от чего не защищает,
и как сообщить об уязвимости.

## Как сообщить об уязвимости

Через приватный канал GitHub: вкладка **Security → Report a vulnerability**
(GitHub Security Advisories). Не открывайте обычный issue и не описывайте
проблему в pull request — это делает уязвимость публичной до исправления.

Пожалуйста, приложите версию приложения, шаги воспроизведения и оценку
влияния. Мы отвечаем на сообщение и держим вас в курсе до выпуска исправления.

## Модель угроз

Кого мы считаем противником:

| Угроза | Защита |
|---|---|
| Кража или потеря устройства | Seed зашифрован ключом из PIN и ключом Android Keystore; без PIN расшифровка невозможна даже с полным дампом хранилища |
| Другое приложение на устройстве | Никаких экспортируемых компонентов с доступом к ключам; данные вне общих каталогов; резервное копирование отключено |
| Резервная копия и перенос на новое устройство | `allowBackup=false` плюс правила `data_extraction_rules.xml`, запрещающие и облачный бэкап, и прямой перенос |
| Подглядывание за экраном, скриншоты | `FLAG_SECURE` на экранах seed, приватного ключа и подтверждения (этап 1) |
| Скам-dApp, вредоносная транзакция | Симуляция и человекочитаемый предпросмотр перед подписью, предупреждение о безлимитном `approve`, экран отзыва разрешений (этап 3) |
| Подмена адреса получателя | Проверка контрольной суммы, сверка вставленного из буфера значения, детект похожих адресов из истории, предупреждение о первом переводе на новый адрес (этап 3) |
| Скомпрометированный или подменённый RPC | Узел не может украсть ключи, но может врать о балансе и комиссии: несколько независимых источников и failover, проверка ответов на согласованность |
| Вредоносная зависимость в цепочке сборки | Минимум зависимостей в криптографических модулях, все версии зафиксированы в одном каталоге, обновления проходят ревью |
| Утечка секрета в репозиторий | `gitleaks` в pre-commit и обязательной проверке CI, `secrets.properties` в `.gitignore` |

Чего мы **не** обещаем:

- защиты на устройстве с root или скомпрометированной ОС, где атакующий
  целенаправленно охотится за этим приложением;
- защиты, если пользователь ввёл seed-фразу куда-то ещё;
- защиты от физического доступа к разблокированному устройству с введённым PIN;
- анонимности: публичные RPC и API видят IP-адрес и запрашиваемые адреса
  кошелька. Кому именно уходят запросы, перечислено в
  `secrets.defaults.properties`, и любой эндпоинт заменяется своим.

## Границы доверия

```
                     ┌──────────────────────────────┐
   ключи, seed  ───▶ │ security/keystore            │  Android Keystore, StrongBox
                     │ security/mnemonic            │  seed в памяти только как ByteArray
                     └──────────────┬───────────────┘
                                    │ подписанные байты, наружу ключи не выходят
                     ┌──────────────▼───────────────┐
                     │ chain/*                      │  формирование и подпись транзакций
                     └──────────────┬───────────────┘
                                    │ только публичные данные
                     ┌──────────────▼───────────────┐
                     │ data/*, feature/*, сеть      │  недоверенные внешние ответы
                     └──────────────────────────────┘
```

Ключевой материал не пересекает верхнюю границу ни в каком виде.
Всё, что приходит из сети, считается недоверенным вводом.

## Правила, обязательные для кода

1. Логирование — только через `WexLog` из `core:common`. Он принимает строки,
   а не произвольные объекты, чей `toString()` может незаметно раскрыть
   содержимое. Для адресов есть `WexLog.redact`.
2. Секреты не логируются никогда и ни на каком уровне. Для них нет и не будет
   перегрузки в этом API.
3. Seed и приватные ключи живут в памяти как `ByteArray`/`CharArray`
   с занулением после использования. Никогда как `String`, никогда в `Bundle`
   или `savedInstanceState`.
4. Денежные величины — только целочисленные (`BigInteger`) в минимальных
   единицах. `Double` и `Float` в денежных расчётах запрещены.
5. Новая зависимость в `security/*` или `chain/*` требует отдельного
   обсуждения в issue до открытия pull request.
6. R8 в релизе обязателен, отладочные логи вырезаются правилами из
   `app/src/main/keepRules/`.

воспроизвести и проверить кто угодно.
