Некастодиальный мультичейн-кошелёк для Android. Не пытается изобрести новую
категорию — пытается выиграть на том, что люди делают каждый день: понятно
подписывать транзакции, быстро отправлять средства и не спотыкаться о комиссии.

> **Статус: этап 0 — фундамент.** Работы с ключами и сетью пока нет.
> Собирается, запускается, показывает состояние конфигурации сборки.
> Дорожная карта — ниже.

## Быстрый старт

```bash
git clone <адрес репозитория>
cd WexWallet
./gradlew assembleDebug
```

Больше ничего не нужно: **ни одного API-ключа, ни одного токена доступа**.
Это правило проекта, а не приятное совпадение — см. [Конфигурация](#конфигурация).

Требуется Android SDK 37 (`local.properties` создаст Android Studio) и JDK 21 —
Gradle скачает его сам, если в системе нет подходящего.

## Что делает кошелёк удобнее

Три вещи, вокруг которых строится продукт. Всё остальное подчинено им.

**1. Понятная подпись и защита от скама.** Перед подписью экран отвечает на
четыре вопроса: что вы отдаёте, что получаете, сколько стоит комиссия и каким
станет баланс. Данные берутся из симуляции транзакции, а не из угадывания.
Безлимитный `approve` помечается явно, есть экран отзыва разрешений,
адреса проверяются на подмену похожим (address poisoning).

**2. Скорость повседневных действий.** Отправка — три экрана, повтор перевода —
один. Недавние получатели, адресная книга, сканер QR с главного экрана.
Зависшую транзакцию можно ускорить или отменить одной кнопкой там, где сеть
это позволяет — а где не позволяет, кошелёк честно об этом говорит.

**3. Газ без боли.** «Не хватит на комиссию» показывается до ввода суммы и с
конкретной цифрой, сколько не хватает. Кнопка «отправить максимум» считает
комиссию правильно. Пресеты скорости понятны без знания слова «gwei».

## Сети

Ethereum, Base, Arbitrum, Optimism, Polygon, BNB Smart Chain, Bitcoin, Solana, TON.

Сети подключаются по очереди, каждая — отдельным этапом за общим интерфейсом
`ChainAdapter`, чтобы добавление новой не требовало трогать UI.

## Архитектура

Многомодульный Gradle-проект. Границы модулей выбраны так, чтобы аудит
безопасности сводился к четырём модулям, а не ко всему коду.

```
build-logic/          convention-плагины сборки (исходники, не бинарник)
app/                  Application, навигация, DI-граф
core/
  common/             логирование без утечек, общие утилиты
  designsystem/       тема, токены, компоненты
security/    ← АУДИТ  ключи, шифрование, seed        (этап 1)
chain/       ← АУДИТ  подпись и работа с сетями       (этапы 3, 5-7)
data/                 балансы, история, контакты      (этапы 3-4)
feature/              экраны                          (этапы 2+)
```

Правило зависимостей: `feature → data → chain → core`. Модули `security/*`
доступны только `data:accounts` и `feature:security`.

Стек: Kotlin, Jetpack Compose + Material 3, Coroutines, Room, DataStore,
Ktor. Криптография — библиотеки с Maven Central, без нативных зависимостей,
требующих авторизации для сборки: см.
[ADR 0001](docs/adr/0001-crypto-stack.md), где объяснено, почему проект
не использует Trust Wallet Core.

## Конфигурация

Приложение обязано собираться и работать без единого ключа. Ключи только
улучшают качество данных: без `ETHERSCAN_API_KEY` не будет истории транзакций,
но баланс и отправка работают через публичные RPC.

Проверить, что подхватилось (значения не печатаются, только имена ключей):

```bash
./gradlew :app:secretsStatus
```

Задать свои ключи:

```bash
cp secrets.properties.example secrets.properties
```

Файл `secrets.properties` в `.gitignore`. То же самое можно сделать через
переменные окружения с теми же именами — так ключи подставляет CI.
Полный список ключей и значения по умолчанию — в `secrets.defaults.properties`,
который коммитится и служит схемой: ключ, которого там нет, задать нельзя.

**Честное ограничение.** Любой ключ, попавший в APK, извлекается из него за
несколько минут. Открытость репозитория ничего здесь не ухудшает, а
`secrets.properties` не делает ключ секретным в собранном приложении. Поэтому
ключи релизных сборок ограничиваются по подписи приложения и квоте и подлежат
ротации, а всё, что требует настоящей секретности, в клиенте не живёт.

## Качество

```bash
./gradlew build          # сборка, unit-тесты, detekt, Android Lint
./gradlew detekt         # только статический анализ
./gradlew testDebugUnitTest
```

Для кода, который считает подписи и адреса, тесты на официальных векторах
(BIP39/BIP32/SLIP-0010, EIP-155/1559/712, BIP143) обязательны — это условие
приёма изменения, а не пожелание.
